## 1. 本轮已落地

### 1.1 行业 Pack 安装与持久化

迁移 `0057_industry_pack_runtime` 新增：

- `service_provider_registry`
- `industry_pack_installations`
- `industry_pack_upgrades`

安装 API：

```text
GET  /api/v1/industry-packs
GET  /api/v1/industry-packs/{pack_key}
GET  /api/v1/industry-packs/installations
POST /api/v1/industry-packs/{pack_key}/install
POST /api/v1/industry-packs/installations/{id}/upgrade-preview
POST /api/v1/industry-packs/installations/{id}/upgrade
```

安装会真实创建场景草稿和服务应用草稿，保存 Pack 版本、模板摘要、安装基线、场景映射和 Provider 元数据；安装幂等，同一 Pack + 应用 + 摘要返回已有安装，不自动发布，不覆盖本地草稿。

### 1.2 Provider 注册表

支持三类能力：

- `object`
- `tool`
- `human_queue`

作用域为租户 + business + workspace。已实现列表、详情、创建、更新、revision 冲突控制、启用状态、幂等未启用占位和审计事件：

```text
service_provider.created
service_provider.updated
```

API：

```text
GET  /api/v1/service-providers
GET  /api/v1/service-providers/{kind}/{key}
POST /api/v1/service-providers
PUT  /api/v1/service-providers/{kind}/{key}
```

注册表当前是能力声明和连接配置，不是真实执行器。真实鉴权、调用、重试、超时、健康检查和可观测性仍未实现。

### 1.3 模板升级与三方合并

三方输入：

- `base`：安装时保存的模板基线。
- `local`：租户当前场景或应用草稿。
- `incoming`：目标 Pack 版本编译出的模板。

合并规则：

- `entries / facts / decisions / recommendations / handlers` 按 `key`。
- `options` 按 `value`。
- `fallback_order` 和其他普通列表按稳定 JSON 值。
- 冲突保留 local，并阻断升级应用。
- 合并结果必须重新通过 `ScenarioConfig` 校验。
- 预览和应用均写 `industry_pack_upgrades`。
- 应用前检查场景和应用 `draft_revision`，预览后配置漂移会返回 stale 冲突。
- 升级成功后只写草稿，不自动发布。

### 1.4 发布门禁

readiness 对 Pack 场景新增：

- `template-maturity`
- `provider-capability`

规则：

- `alpha`：必阻断，只允许验证和模拟。
- `beta`：应用存在 `canary` 渠道时放行；否则阻断。
- `ga`：正常参与发布检查。
- 对象、工具或人工队列 Provider 缺失：阻断。
- 普通非 Pack 场景：保持原行为。
- readiness 文案不泄露 Provider key、工具标识和队列名。

场景级发布接口直接阻止 `alpha`：

```text
409 scenario_alpha_publish_forbidden
```

因此不能通过单独发布场景绕过应用 readiness。

### 1.5 前端

新增服务应用内部路由：

```text
/service-apps/industry
```

页面包含三个页签：

- 行业模板：查看成熟度、对象数、场景数并安装。
- 接入能力：管理 object / tool / human_queue Provider。
- 升级记录：预览三方合并、展示冲突路径、应用无冲突升级。

该入口不新增一级导航，不恢复独立 `/service-scenarios` 页面。readiness 面板同步展示新的成熟度和 Provider 检查。

## 5. 尚未完成

1. **真实 Provider 与工具执行**：注册表尚未连接真实业务系统，没有凭证托管、鉴权、超时、重试、限流、健康检查和可观测性闭环。
2. **真实渠道入站联调**：人工工作台上下文已可用，但企微/飞书从入站、场景执行到转人工 handoff 的全链路仍需验收。
3. **场景轨迹真实写入**：目前只有模拟入口写轨迹，真实会话还没有 `simulation=false` 的执行证据。
4. **生产数据验收**：需要真实订单、账号、退款、物流和人工队列数据验证权限、脱敏、幂等、失败和结果未知语义。
5. **升级治理**：尚缺升级回滚、逐字段冲突解决 UI、批量升级和灰度升级策略。
6. **Pack 分发**：当前只有内置 Pack 目录，尚无外部包安装、签名、来源验证和版本市场。
7. **生产运营**：容量、监控、告警、审计留存、灾备和发布回滚演练仍未完成。
8. **动态门禁文案多语言**：后端返回的检查文案仍以中文为主，直接渲染后端文本的非中文界面会回退中文。
9. **场景版本固化**：会话创建时尚未固化场景版本。
10. **事实刷新**：人工侧当前只返回轨迹快照，`refresh` 策略尚未落地。

## 6. 当前结论

行业 Pack 运行时开发闭环已经形成：

```text
编译 Pack
  → 安装场景/应用草稿
  → 注册 Provider 占位
  → 配置接入能力
  → readiness 检查成熟度和能力
  → 升级预览/三方合并
  → 草稿更新
  → 人工发布
```

但真实执行链路和生产验收尚未完成，当前应描述为“开发版本已落地、可进入联调验收”，不能描述为“生产可用”。
