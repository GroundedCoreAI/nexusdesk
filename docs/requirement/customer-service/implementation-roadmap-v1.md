## 0. 产品目标

客服模块最终交付的不是一组孤立页面，而是一套可配置、可预览、可调试、可发布、可运营的服务交付平台。

```text
服务应用（交付单元）
  ├─ 服务目录（客户看到什么）
  ├─ 服务场景（客户要完成什么任务）
  ├─ 业务对象（客户在处理什么）
  ├─ 业务事实（客户和坐席需要看到什么）
  ├─ 用户决策（客户要确认什么）
  ├─ 执行能力（查询、知识、办理、Agent、人工、追踪）
  └─ 客户渠道（从哪里进入）
```

核心产品判断：

1. 服务应用是交付单元。
2. 服务场景是核心可复用资产。
3. 业务对象是客户可交互的一等产品组件。
4. Agent 是场景的一种执行能力，不是场景本身。
5. 人工工作台继承场景、对象、事实、决策、动作和轨迹。
6. 行业差异通过模板、配置和注册表表达，不通过运行时行业分支表达。
7. 模拟、待确认、处理中、成功、失败、结果未知和转人工必须明确区分。

## 1. 当前基线

### 1.1 已具备

- 服务场景草稿、发布、版本、回滚和轨迹。
- 服务应用组合、版本、发布和回滚。
- 应用级服务目录、场景引用、能力、执行顺序和客户渠道。
- 客户统一体验入口和场景模拟。
- 场景配置、发布检查和模拟轨迹。
- 路由决策记录。
- 人工交接队列、接管、恢复和关闭。
- 人工工作台 V1 前端。
- 应用发布完整性后端强制门禁与逐场景检查。
- 场景发布完整性检查前端，且与后端判定一致。
- 多行业场景包编译器。
- 内容社区 Pack（6 类对象、11 个场景）。
- 本地生活 Pack（4 类对象、6 个场景），验证零核心模型改动。
- 行业 Pack 安装接口与租户持久化（安装记录、场景模板版本快照）。
- 模板升级：三方合并、冲突预览、冲突阻断和 revision 漂移检测。
- 对象、工具和人工队列的统一 Provider 注册表。
- 成熟度发布门禁：`alpha` 阻断、`beta` 需灰度渠道、`ga` 正常。
- 场景级发布接口直接阻止 `alpha`。
- 应用内“行业能力”页：模板安装、接入能力和升级记录。
- 人工工作台业务上下文聚合接口（`GET /handoffs/{id}/context`）。
- 场景轨迹可绑定会话。

### 1.2 当前关键缺口

- 运行时尚未执行服务场景：入口决策只有 `defer / reject / request_handoff / submit_agent_run`，没有“分发到场景”的动作，真实会话不会产生 `simulation=false` 轨迹。
- Provider 注册表目前只服务发布门禁的能力核对，运行时不会解析它去拉取业务对象或调用工具。
- 会话创建时未固化场景与场景版本，只能从最近一条轨迹反推。
- 事实刷新策略（`refresh`）未在运行时与人工侧落地，当前只返回轨迹快照。
- 真实渠道 handoff 入站全链路尚未完成联调；当前验证使用平台 API 创建的会话。
- 当前仅支持内置 Pack 目录，尚无外部包分发、签名和来源验证。
- 模板升级尚缺回滚、逐字段冲突解决 UI 和批量升级。
- 真实订单、账号、退款、物流和人工队列的生产数据验收尚未完成。
- `human-workbench-v1.md`、`implementation-roadmap-v1.md`、`industry-pack-v1.md` 缺英文对照，未满足仓库双语要求。
- 动态门禁文案前端已走多语言键，但后端仍返回中文文案，直接渲染后端文本的界面会回退中文。

## 2. 阶段路线

### 阶段 1：统一客户体验

目标：客户能从服务应用进入目录、选择场景、绑定对象、查看业务事实、完成决策并得到明确结果。

工作内容：

- 服务目录搜索、分类和场景卡片。
- 业务对象选择与候选状态。
- 业务事实投影和空状态。
- 用户决策、确认和纠错。
- 成功、失败、待确认、处理中、转人工和结果未知的差异化展示。
- 统一体验入口，不暴露内部 Provider、工具和规则标识。

验收：

- 客户可在两个以上业务对象之间切换。
- 任意结果状态都有明确下一步。
- 无对象、权限不足、对象失效和人工兜底路径可用。
- 移动端可正常使用。

### 阶段 2：发布完整性门禁

目标：配置不完整的场景或应用不能正式发布，且前端提示与后端判定一致。

状态：已完成。前端三个发布入口统一接入后端 `readiness`；后端在发布事务内重新读取配置并强制校验，`blocked` 和 `simulate_only` 均返回 409，且不改变版本、revision 或状态。行业 Pack 场景额外检查模板成熟度和 Provider 能力：`alpha` 必阻断，`beta` 无灰度渠道阻断，`ga` 正常；场景级发布接口也直接阻止 `alpha`。

工作内容：

- 场景关联与启用检查。
- 业务对象、事实、处理能力和兜底顺序检查。
- 办理场景确认检查。
- 人工承接和客户渠道检查。
- 场景发布状态和未发布修改提示。
- 应用级聚合门禁和逐场景解释。
- Pack 模板成熟度检查。
- Pack 场景 Provider 能力检查。
- 后端在发布事务内重新校验，不能信任前端结果。

验收：

- `blocked` 阻止模拟和发布中不适用的部分。
- `simulate_only` 可以模拟但不能正式发布。
- 只有全部场景 `ready` 时应用可发布。
- 直接调用发布 API 也无法绕过门禁。
- 前端门禁与后端门禁结果一致。
- `alpha` 场景不能绕过应用门禁单独发布。
- `beta` 场景只有在应用配置灰度渠道后才可通过。

### 阶段 3：人工工作台

目标：人工坐席能接管服务场景，并继承完整业务上下文。

状态：V1 已完成队列、详情、搜索、筛选、接管、恢复、关闭、revision 冲突处理、只读角色限制和四语言文案。`GET /api/v1/handoffs/{id}/context` 已完成场景、对象、事实、决策、运行和路由证据聚合，并在服务端完成权限裁剪与脱敏；平台 API 创建的会话已完成接管、恢复和关闭联调。真实渠道入站 handoff 全链路仍待验收。

工作内容：

- 实时队列、状态筛选和搜索。
- 接管、恢复 Agent、关闭会话。
- 会话摘要、最近消息、待确认动作和最近运行。
- 场景、业务对象、事实、用户决策和路由原因聚合。
- 权限、脱敏、revision 冲突和异常状态。
- 处理结果和审计。
- 真实渠道 handoff 入站、场景执行和接管/关闭全链路联调。

验收：

- 坐席无需客户重复描述订单、账号等对象。
- 坐席能看到自动服务做到哪一步以及为什么转人工。
- 并发接管不会覆盖他人操作。
- 恢复和关闭语义明确区分。

### 阶段 4：多行业场景包

目标：新增行业只增加资产和模板，不改核心场景、应用和运行时分支。

状态：开发版本闭环已落地。编译器、内容社区 Pack、本地生活 Pack、安装 API、租户持久化、场景/应用草稿创建、Provider 注册表、模板升级三方合并、成熟度发布门禁和前端行业能力页均已完成；真实 Provider/工具执行、真实渠道联调和生产数据验收待补。

工作内容：

- Pack 清单、场景模板、对象模板和策略模板。
- 应用蓝图编译。
- 样例数据和验收用例引用校验。
- 内容社区完整 Pack。
- 本地生活第二行业验证。
- 模板版本、企业实例、升级预览和回滚。
- Provider、工具和队列注册表。
- Pack 安装幂等、安装基线和冲突保护。
- 场景与应用草稿安装，不自动发布。
- `alpha / beta / ga` readiness 和场景发布门禁。
- 行业能力管理页：模板安装、接入能力和升级记录。

验收：

- 内容社区 6 类对象、11 个场景可编译。
- 3 个 `ga` 场景可发布，`beta` 可灰度，`alpha` 只能模拟。
- 第二行业包不修改核心模型即可接入。
- 运行时不存在 `if industry` 或 `if pack_key` 业务分支。
- 现有购物消费应用回归通过。
- 安装和升级只写草稿，不覆盖本地修改；冲突时阻断应用。
- Provider 缺失、`alpha` 和无灰度渠道的 `beta` 不能通过生产发布。
- 真实 Provider、工具执行和渠道联调完成前，不宣称生产可用。

### 阶段 5：质量与运营

目标：从“能配置”进入“可持续运营”。

工作内容：

- 自动解决率、转人工率、修正率、重复咨询率。
- 场景、对象、模板和行业包维度指标。
- 结果未知和失败原因分类。
- 模板升级冲突与发布门禁运营视图。
- 人工工作台超时、优先级和坐席负载。
- 模拟回归和发布前验收用例。

验收：

- 每个场景可解释流量、成功、失败和转人工。
- 发布新版本前能自动执行必选模拟用例。
- 结果未知不会被统计为成功。
- 可按 Pack 和模板追踪升级质量。

## 3. 实施顺序

```text
统一客户体验
  → 发布完整性前端门禁
  → 后端强制门禁
  → 人工工作台实时队列
  → 工作台业务上下文继承
  → 行业包编译器
  → 内容社区 Pack
  → Pack 安装与 Provider 注册表
  → 本地生活 Pack
  → 模板升级三方合并
  → 成熟度发布门禁
  → 真实 Provider / 渠道 / 生产数据验收
  → 运营治理
```

原则：

1. 先打通完整电商客服主链路。
2. 再抽象人工承接和行业模板。
3. 第二个行业用于验证抽象，不用来堆场景数量。
4. 小问题在回归测试中收敛，不在每次增量重新设计全平台。

## 4. 本阶段并行工作拆分

### A. 客户体验

- 服务目录与分类筛选。
- 结果状态细分。
- 移动端和空状态。
- 业务化文案。

### B. 发布门禁

- 前端逐场景检查。
- 应用级发布拦截。
- 后端强制校验。
- 门禁 API 与测试。

### C. 人工工作台

- 队列和详情。
- 接管和恢复。
- 上下文聚合。
- 权限与并发。

### D. 行业包

- 编译器和清单校验。
- 内容社区资产。
- 应用蓝图。
- 样例与验收。
- 安装、持久化和幂等。
- Provider 注册表。
- 三方合并和升级预览。
- 成熟度与 Provider 发布门禁。
- 行业能力管理页。

### E. 回归与联调

- 前后端构建。
- 数据库/中间件启动。
- 真实登录与 API 冒烟。
- 真实 Provider、工具和人工队列联调。
- 真实渠道 handoff 入站验收。
- 浏览器可视化回归。
- 既有页面无回归。

## 5. 验收矩阵

| 能力 | 单元测试 | API 测试 | 浏览器回归 | 真实数据 |
|---|---|---|---|---|
| 客户统一体验 | 场景配置映射 | 模拟接口 | 必选 | 一个已发布应用 |
| 发布门禁 | 规则函数 | 发布阻断/放行 | 必选 | 至少一个阻断场景 |
| 人工工作台 | 状态转换 | 接管/恢复/关闭 | 必选 | 至少一个 handoff |
| 行业包 | 编译、安装、幂等 | 安装与草稿创建 | 行业能力页 | 内容社区草案 |
| Provider | 注册表规则 | CRUD/revision/占位 | 接入能力页 | 真实 Provider 待接 |
| 模板升级 | 三方合并 | 预览/冲突/应用 | 升级记录页 | 两版模板 |
| 成熟度门禁 | `alpha/beta/ga` | 场景与应用发布阻断 | 门禁文案 | 灰度渠道验收 |

## 6. 不可破坏的约束

- 不修改 `backend/.env` 中的密码开关。
- 不在核心平台引入行业专属枚举或业务词。
- 不新增行业专属核心表。
- 不允许前端判定替代后端权限和发布校验。
- 不允许未知结果显示为成功。
- 不允许 Agent 配置和服务场景配置互相复制。
- 不允许人工工作台绕过租户和业务范围。
- 不重新启用未经过产品确认的独立“审核工作”入口。
- 不为了行业数量牺牲主业务链路完整性。

## 7. 待产品确认

1. 人工工作台 V2 是否需要坐席状态、班组和在线路由。
2. 服务场景是否需在会话创建时固化场景版本，还是由首条路由决策绑定。
3. 未知结果是否需要独立运营队列。
4. `beta` 行业场景当前由应用是否存在 `canary` 渠道控制，是否需要细化到渠道人群、租户或应用版本。
5. 真实 Provider 注册后，凭证托管、健康检查、失败重试和结果未知语义由平台还是业务适配器负责。
6. 模板升级是否需要回滚、批量升级和逐字段冲突解决 UI。
