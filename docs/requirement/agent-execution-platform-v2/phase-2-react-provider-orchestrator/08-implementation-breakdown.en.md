### R2 — Execution and Agent Identity

### R3 — Registry and Synchronous/Asynchronous Assembly

- Registry factories remain synchronous, zero-argument, fresh-instance factories; async factories and await inside synchronous resolve are forbidden.
- In one synchronous no-`await` section, Orchestrator sets the private execution `ContextVar`, indirectly calls `registry.resolve`, and resets in `finally`; the application zero-argument factory reads and validates `ExecutionContext`, captures it and RuntimeFactory into a new ReactAdapter, and the Adapter never reads ContextVar afterward. **Context contains neither worker_emit nor runtime_emit**.
- `worker_emit` is a separate Worker→`orchestrator.execute(context, worker_emit)` argument and the sole existing Worker callback writing Repository/Notifier; only Worker/Orchestrator may hold it, and Factory/PlatformTools/RuntimeEngine cannot reach it.
- The Adapter runner creates private `runtime_emit` and passes the same function object with the same claimed row to both `await RuntimeFactory.for_run(row, runtime_emit)` and `runtime.run(..., runtime_emit, ...)`; it only performs `(kind,data)→AgentEvent→React-private stream` and never directly writes Repository/Notifier. Core imports no applications/business and the application composition root injects the capability.
- Missing Context, wrong type, overwritten Context, repeated start, and factory exceptions fail safely and clean up; `agent_model_required` retains its legacy code in the Adapter lifecycle rather than becoming `adapter_factory_failed`; enabled-path failure never silently falls back to legacy.
- Deterministic tests and spies cover task-concurrent isolation, nested reset, resolve/factory-exception cleanup, missing/overwritten Context, identical runtime_emit at for_run/run, events reaching Orchestrator-owned worker_emit only through the public stream, and multiple Runs sharing no row/history/dual emits/queue/runner/result.

### R4 — Public Result, Private Outcome, Errors, and Usage

- history/dropped reach Worker Memory completion hooks only after successful execution, never failure/cancellation. usage is never `None`; React v1 Runtime currently returns only output/history/dropped, so without aggregation input both public Result and private Outcome usage are `{}`, neither an existing aggregate nor fabricated zero tokens. `model.completed` usage remains verbatim and is not repurposed into Result aggregation.
- The error matrix in 03 section 6.1 covers every Phase 0 source: beyond literal Engine/Factory errors it includes `model_resource_not_found/model_resource_disabled/model_profile_version_not_found/model_input_too_large/model_tools_not_supported`, `model_provider_unavailable/model_rate_limited/model_provider_rejected/model_transport_error`, `content_blocked_input/content_blocked_output`, `gateway_concurrency_exceeded/gateway_request_quota_exceeded`, and `model_credential_unavailable/model_response_too_large/model_stream_interrupted`; `model_stream_not_supported` currently falls back. RuntimeFault `model_timeout` remains separate from outer `run_timeout`; reserved/malformed events and ack protocol errors produce safe protocol_error.
- Every RuntimeFault, including a future unknown one, retains its original private legacy_error_code verbatim; public mapping follows the known table or safe internal_error fallback without copying Provider/Domain text. Unknown ordinary exceptions and ordinary stream/worker_emit failures map to public `internal_error` plus legacy `execution_error`; CancelledError from stale/cancelled/expired append is control flow outside ordinary error mapping.
- Explicit cancel has no ExecutionError; heartbeat loss produces failed/worker_lost through Worker; caller CancelledError cleans up and re-raises. Never disclose Provider raw text, stack, input/config/history, secrets, or nil.

### R6 — Events, Backpressure, Acknowledgment, and Terminal Publication

- Every valid ordinary business event passes under its original name with identical JSON payload through private runtime_emit→React-private stream→public stream→Orchestrator worker_emit, including `model.delta`, `knowledge.retrieved`, `memory_search.completed`, and extension events, with no allowlist; raw Adapter `run.*`, `tool.replay`, or malformed events produce safe protocol_error before worker_emit.
- `run.*` is Repository-only and `tool.replay` DurableToolReplayCache-only; after the same dual-emit/ack boundary `model.delta` still uses worker_emit→Notifier best-effort with no DB sequence/replay. AgentEvent uses UUID event_id, UTC timestamp, Adapter-local monotonic sequence, and `source=engine_native`, changing neither DB event_seq nor SSE ID.
- start creates runner and a closed first-emission gate; before synchronous `stream_events` claim returns, it atomically changes never-claimed to claimed-active and releases the gate, and runner cannot emit into the stream beforehand, so start→immediate-stream loses no first event. Normal Orchestrator fixes start→claim→release→drain→collect and never depends on a race.
- A lone no-stream collector on never-claimed explicitly selects **React-private no-stream suppression** and releases the gate; events neither enqueue nor block, and a later stream is empty/ends under terminal semantics with no replay. **Never claim equivalence to LocalTest**. First collect/stream selection linearizes as first-call-wins under one state lock.
- Explicitly define never-claimed, claimed-active, closed, and terminal; cancel/aclose wakes the first-emission gate and put/get, closed cannot be claimed again, and first stream after never-claimed no-stream/cancel terminal is empty. LocalTest retains its own pre-claim queueing, terminal discard, and yield=delivery.
- Recommended Condition plus bounded deque tracks these states, producer finished, terminal published, queued/in-flight undelivered, settled ack identities, pending result, shielded terminal future, and runner under one state. Capacity is at least one and limits only queued buffer, allowing one additional yielded in-flight event; an active full stream waits on Condition.
- Core-private `AcknowledgingEventStream` is `AsyncIterator[AgentEvent]+acknowledge(event)+abort(error)/aclose` and imports no React. Pop/yield is not React delivery; only after successful awaited worker_emit does Orchestrator acknowledge the current unique in-flight event by execution_id/event_id and decrement exactly once. Repeated settled ack is idempotent; wrong identity, no in-flight, out-of-order, or cross-execution ack produces safe protocol_error and abort, and bare yield never automatically acknowledges.
- Normal runner completion stores pending result first and publishes the unique Result once producer is finished and queued+in-flight undelivered=0, without an idle unclosed claimed stream blocking collect. Normal Orchestrator drains stream before collect and Worker finishes last, keeping Repository run.* terminal frames last.
- cancel, aclose, and ordinary stream/worker_emit failure atomically suppress queued/late events, wake gate/put/get, cancel and drain runner, and suppress late success. Explicit cancel uses Adapter-internal first-terminal-wins, returns cancelled with no output/error, and never retroactively cancels a completed Result; ordinary failure is failed, not cancelled.
- Stale/cancelled/expired `worker_emit→Repository.append` raises `asyncio.CancelledError`, remains unacknowledged/unpersisted, and Orchestrator/Adapter aborts/acloses then re-raises without changing the original terminal state or mapping to ordinary execution_error; only stale/terminal/wrong-owner/expired finish silently no-ops.
- Runner stream/protocol failure is safely raised to the stream consumer, treated as delivered to release waiters, and then publishes failed Result; specified PG/OS delta failures already swallowed by Notifier acknowledge normally, while other exceptions follow worker_emit failure.
- A lone no-stream collector cancellation stops execution; shared collectors are shielded; caller CancelledError cleans up and re-raises. Every owned task is ultimately awaited/done; bounded drain under outer timeout is promised only for cooperative coroutines, with no forced-kill promise for non-cooperative coroutines.
- Event/gate deterministic tests and dual-emit spies cover first event, four stream states, queue size one, multiple events and slow worker_emit, ack identity/duplicates/order, immediate/concurrent/repeated collect, blocked producer/consumer cancellation, aclose, append/Notifier failure, both persistence commit orders, late events/results, and task completion; never rely on sleep coincidence.

### R10 — Cancellation, Timeout, and Lease Races

- Explicit `adapter.cancel` uses Adapter-internal first-terminal-wins and returns cancelled with no output/error; a completed Result is never retroactively cancelled. Orchestrator caller CancelledError cleans up and re-raises; ordinary execution/worker_emit errors are failed.
- Worker uses `monitor_failure` to distinguish user cancelled from failed/worker_lost; lease loss never masquerades as user cancellation, and model_timeout/run_timeout remain distinct.
- Stale/terminal/wrong-owner/expired finish silently no-ops; stale/cancelled/expired append raises `asyncio.CancelledError`, remains unacknowledged/unpersisted, cleans up and re-raises without changing the original terminal state, and is never described as append no-op or ordinary execution_error.
- Run persistence uses submission-order **first-commit-wins**, not unconditional cancellation precedence: finish/reaper-first makes cancel a no-op, while cancel-first prevents late-finish overwrite. Retain reaper cancelled-with-worker_lost/queue_timeout variants. Deterministic tests cover both orders plus cancellation, timeout, completion, and lease-loss races, producing one terminal state with no automatic retry, Fencing Token, or new side-effect rollback semantics.
