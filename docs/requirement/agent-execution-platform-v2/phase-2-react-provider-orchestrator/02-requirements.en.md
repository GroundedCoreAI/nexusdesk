## User Stories

**US-1 (Existing tenant user)**: As a user of an existing Agent, I want no Agent configuration or client changes after the internal refactor so that I continue to receive the same replies, events, cancellation, and terminal behavior.

**US-2 (Platform engineer)**: As a platform engineer, I want React to run through a common Adapter and orchestrator so that future Engines do not require changes to Worker core logic.

**US-3 (Platform operator)**: As a platform operator, I want the new path default-off, gradual, and reversible so that I can restore legacy execution without database operations if problems occur.

**US-4 (QA/SRE)**: As QA/SRE, I want to compare old/new output, events, errors, and terminal states so that repeatable evidence determines whether migration caused regressions.

## Functional Requirements

### FR-1 React Engine Adapter

| Item | Description |
|---|---|
| Trigger | When the new-path orchestrator resolves a claimed Run to the fixed `react/native/v1` identity and starts the Adapter |
| Input | The unchanged Phase 1 ExecutionRequest plus private ExecutionContext (same claimed row, history, summary/customer_memory, trace/timeout, and related values); `worker_emit` is a separate Worker→Orchestrator argument and never enters Context/Adapter/RuntimeFactory; RuntimeEngine is still built by the existing RuntimeFactory |
| Identity and capabilities | The ExecutionContext-private boundary normalizes Execution UUIDs under R16: an exact stdlib UUID is returned unchanged with its object identity preserved, while a UUID subclass such as asyncpg's return type undergoes controlled value conversion such as `UUID(str(value))` to produce an exact stdlib UUID. Normalize `row.id` and the supplied `execution_id` separately and compare their values with `==`, never `is`. Public `ExecutionRequest.execution_id` must be an exact stdlib UUID whose value directly equals the claimed row ID; transient canonical parsing is not public stringification. Context retains the same original claimed Mapping, the original `row.id` is never copied, replaced, or rewritten, and RuntimeFactory continues to receive the original row. Reject strings, integers, None, forged non-UUID values, and value mismatches safely. Ordinary exceptions raised by a malicious subclass `__str__` or descriptor become safe static `INVALID_REQUEST`, while control-flow exceptions re-raise unchanged. With a snapshot, strictly parse the real UUID from `config.agent.id`; missing, malformed, or nil values fail safely. Only a no-snapshot React Run using legacy base_runtime may use `UUID(int=0)` as an anonymous unbound internal sentinel; never borrow a Run/conversation UUID. Adapter identity is react/native/v1; streaming/cancellation/tool_calling/native_events=true and every unsupported capability=false |
| Output | All five methods and a safe public ExecutionResult. Private ExecutionOutcome explicitly carries output, history, dropped, legacy error_code, non-optional usage, and related private values; history/dropped never hide in public engine_metadata. ReactAdapter additionally implements Core-private `async collect_outcome(handle)`, reusing the same terminal/no-stream/collector/cancellation path as public `collect_result` and returning the internally published Outcome; this entry does not join the Phase 1 public protocol. usage is never None. React v1's current Runtime returns only output/history/dropped, so without aggregation input both public Result and private Outcome usage are `{}`, not an existing aggregate or fabricated zero tokens |
| Execution | Registry factories remain synchronous, zero-argument, fresh-instance factories. The application captures ContextVar into a new ReactAdapter in a synchronous no-await scope. The Adapter-private `runtime_emit` is passed to both `RuntimeFactory.for_run(row, runtime_emit)` and `runtime.run(..., runtime_emit, ...)`, and only performs `(kind,data)→AgentEvent→React-private stream`, never direct Repository/Notifier writes. Runtime construction is asynchronous inside the runner, each instance has one active execution, and ReAct is not rewritten |
| Failure handling | Missing/wrong Context, repeated start, RuntimeFault, TimeoutError, and unknown exceptions follow an explicit safe matrix. agent_model_required retains its legacy code inside the Adapter lifecycle rather than becoming adapter_factory_failed; enabled-path failure never silently falls back to legacy |

### FR-2 Execution Orchestrator

| Item | Description |
|---|---|
| Trigger | After Worker claims a Run with the flag on and validates its configuration fingerprint |
| Input | Claimed row, trusted tenant/conversation/agent context, separate `worker_emit` (the sole existing Worker callback that writes Repository/Notifier), and rendered Memory results; Core must not import applications/business modules |
| Output | ExecutionOutcome (status, output, history, dropped, legacy error_code, non-optional usage, and related private values); every execution uses an independent Adapter/Handle and never shares row, history, worker_emit, runtime_emit, queue, or runner |
| Execution | Build Request→fixed selection react/native/v1→in one no-await synchronous section set ContextVar, registry.resolve, and reset in finally→start→synchronously claim stream and open the first-emission gate→only then may runner emit through private runtime_emit→after taking each public-stream event `await worker_emit`, then `acknowledge(event)` on success→fully drain→call React-private `collect_outcome` exactly once, or for protocol-free LocalTest use public `collect_result→ExecutionOutcome.from_result` deterministic fallback; Worker finishes last so run.* terminal frames remain last. Normal orchestration does not depend on a collect/stream race |
| Protocol detection | Core's private runtime-checkable `AcknowledgingEventStream` and `OutcomeCollectingAdapter` helpers import no React, verify genuinely asynchronous capability, and fail closed on descriptor exceptions. React requires ack after successful worker_emit, while LocalTest has no private protocol and explicitly settles Adapter-internal delivery at `yield = delivery`, with Orchestrator still awaiting worker_emit but performing no extra ack. React-private collection never uses lossy fallback. LocalTest fallback reads only the public error code: `execution_timeout→run_timeout`, every other failed Result maps to `execution_error`, completed defaults history/dropped to empty lists, and cancelled has no code. No Factory/PlatformTools/RuntimeEngine event may directly reach worker_emit; exceptions use abort/aclose cleanup |
| Failure handling | Every registry/version/Context/Adapter-stage failure normalizes safely and cleans up without silent fallback; caller and Repository-append CancelledError clean up and re-raise. The production selector fixes the tuple. LocalTest uses a separate Registry/selector with the same Orchestrator/Worker; no latest, fallback, or client Engine selection |

### FR-3 Worker Integration and Retained Responsibilities

| Item | Description |
|---|---|
| Trigger | RuntimeWorker._execute selects a path using the process-startup global flag; queue claim, heartbeat, and finish retain existing logic |
| Input | Claimed row, legacy RuntimeFactory or new Orchestrator, owner, fingerprint, MemoryInjectionPort, and the original event callback as on-path `worker_emit`; only a final `orchestrator=None` constructor parameter is added and the off path remains unchanged |
| Output | Repository.finish parameters and events equivalent to legacy; new-path Worker recognizes neither React nor Codex, and private history/dropped reach Worker Memory completion hooks only after successful execution |
| Execution | Flag off takes the unchanged legacy branch; flag on calls `orchestrator.execute(context, worker_emit)`. Monitor continues heartbeat and cancels the execution task on lease loss/cancellation. Orchestrator claims/drains stream before collect, and Worker finishes afterward |
| Failure handling | monitor_failure distinguishes user cancelled from failed/worker_lost; lease loss never masquerades as user cancellation. Repository remains the sole terminal-state writer: stale/terminal/wrong-owner/expired finish is a silent no-op, while stale/cancelled/expired append raises `asyncio.CancelledError` and must not be described as no-op or ordinary execution_error. Persistence uses submission-order first-commit-wins and reaper behavior is unchanged |

### FR-4 Runtime Events, AgentEvent, React-Private Stream, and SSE Compatibility

| Item | Description |
|---|---|
| Input and passthrough | Every valid ordinary business event passes through private runtime_emit under its original name with the same JSON payload into AgentEvent, then Orchestrator restores and delivers it through worker_emit, including knowledge.retrieved, memory_search.completed, model.delta, and extension events; there is no allowlist. Missing/malformed fields produce safe protocol_error |
| Forbidden forgery | Raw Adapter run.* or tool.replay is safe protocol_error and never reaches worker_emit. run.* is Repository-only and tool.replay is DurableToolReplayCache-only. model.delta ultimately remains Notifier best-effort through worker_emit, with no DB sequence or replay |
| AgentEvent | UUID event_id, UTC timestamp, monotonically increasing Adapter-local sequence, and source=engine_native; it changes neither DB event_seq nor SSE IDs |
| Private structured protocol | Core defines runtime-checkable `AcknowledgingEventStream`: `AsyncIterator[AgentEvent] + acknowledge(event) + abort(error)/aclose`. Ack matches execution_id/event_id against the current unique in-flight event and is exactly-once; repeated settled acknowledgments are idempotent without another decrement, while wrong-identity/out-of-order acknowledgments cause safe protocol failure and abort. Bare yield never automatically acknowledges |
| React first emission and no-stream semantics | Never claim equivalence to LocalTest. After start the first-emission gate is closed and runner cannot emit into the stream before synchronous stream_events claim; normal order is start→claim stream→release→drain→collect. A lone no-stream collector on never-claimed explicitly selects React-private no-stream suppression and releases the gate, after which stream is empty/ends under terminal semantics; cancel/aclose also wake the gate |
| State and backpressure | Explicitly define never-claimed, claimed-active, closed, and terminal; collect/stream races linearize as first-call-wins. Condition plus bounded deque has capacity at least one and limits only queued buffer, with one additional in-flight event allowed. A full claimed-active stream waits; pop/yield is not React delivery, and only ack after successful worker_emit reduces undelivered |
| Terminal and closure | Normal runner completion stores pending result first and publishes the unique Result when producer is finished and queued+in-flight undelivered=0, without letting an idle unclosed claimed stream block collect. At terminal, an active stream drains and ends; closed cannot be claimed again; first stream after never-claimed no-stream/cancel terminal is empty with no replay. Explicit cancel/aclose/ordinary emit failure suppresses late events/results and cleans up |
| SSE | Preserve internal/Open Last-Event-ID, after, draining beyond 200 events, no-ID delta non-replay, hidden tool.replay with cursor advancement, and public-field filtering. The handler manually parses internal Last-Event-ID, returning `400 / invalid_last_event_id` for invalid values or values outside `[0,2147483647]`; FastAPI typed Query/Header validation handles internal after and Open after/Last-Event-ID, returning 422 for type or range errors. Valid cursors combine through `max(after,last_id)` and replay strictly with `seq>after`; never interchange 400 and 422. AgentEvent/Outcome/Context add no HTTP/SSE fields, and routes, schemas, status codes, and error bodies remain unchanged |

### FR-5 Errors, Cancellation, Timeout, and Terminal States

| Item | Description |
|---|---|
| Input | RuntimeFault.code, ExecutionError, cancel_requested, heartbeat state, ExecutionResult, and runtime_emit/worker_emit/stream/append/Notifier exceptions |
| Output | Public errors contain only ExecutionErrorCode and static messages; private Outcome retains every original RuntimeFault code. Existing observable codes including agent_model_required, configuration_changed, Gateway/Domain codes, model/run timeout, execution_error, and worker_lost are preserved |
| Complete source matrix | Besides literal Engine/Factory errors, cover Phase 0 baseline model_resource_not_found/disabled, model_profile_version_not_found, model_input_too_large, model_tools_not_supported, model_provider_unavailable/rate_limited/provider_rejected/transport_error, content_blocked_input/output, gateway_concurrency_exceeded/request_quota_exceeded, model_credential_unavailable, model_response_too_large, and model_stream_interrupted; model_stream_not_supported currently falls back. See 03 section 6.1 for the complete public mapping |
| Unknown codes and exceptions | Every RuntimeFault, even an unrecognized future one, retains its original code in private legacy_error_code; public mapping follows the known table or safe internal_error fallback without copying Provider/Domain text. Unknown ordinary exceptions map to public internal_error plus legacy execution_error. model_timeout and run_timeout remain distinct |
| Append control flow | asyncio.CancelledError from stale/cancelled/expired `worker_emit→Repository.append` is not acknowledged and persists no event; Orchestrator/Adapter abort/aclose clean up and re-raise, with the original terminal state/monitor determining outcome rather than ordinary execution_error. Specified PG/OS delta failures already swallowed by Notifier still acknowledge normally |
| Cancellation | Explicit adapter.cancel uses Adapter-internal first-terminal-wins and returns cancelled with no output/error; a completed Result is never retroactively cancelled. Ordinary stream/worker_emit failure is failed, not cancelled. A lone no-stream collector cancellation stops execution, shared collectors are shielded, and caller CancelledError cleans up and re-raises |
| Persistence races | Run persistence uses submission-order first-commit-wins, not unconditional cancellation precedence: if finish/reaper commits first, cancel is a no-op; if cancel commits first, late finish cannot overwrite. Cover cancelled-with-worker_lost/queue_timeout reaper variants; add no automatic retry, Fencing Token, or side-effect rollback semantics |
| Cleanup | All owned tasks finish. Bounded drain is promised only for cooperative coroutines under an outer timeout, with no forced-kill promise for non-cooperative coroutines |

|---|---|---|---|
| `execution_orchestrator_enabled` (environment variable `AGENT_EXECUTION_ORCHESTRATOR_ENABLED`) | Core Settings / each API or Worker process | `false` | false uses the existing Factory/Runtime; true uses Orchestrator; applied at process startup/rolling restart, never request-hot-switched. Both env examples and necessary compose files receive only interpolation |

| Item | Description |
|---|---|

The flag is excluded from the runtime-composition fingerprint so off API/on Worker and mixed Workers retain the same fingerprint |

## Non-Functional Requirements

- **Performance**: The new path adds only in-process DTO/event mapping. In an equivalent real external environment, use the method in 05 section 4 with at least 30 matched pairs and five warm-up pairs excluded from samples, targeting nearest-rank p95 end-to-end latency increase ≤5%; report first token, raw overhead, and error rate independently. Test doubles support functional tests only and cannot establish production performance; without a real environment the performance submetric is `pending_env`, but fully green functional tests may enter acceptance capped at conditionally passed.
- **Compatibility**: Phase 1 DTOs, Registries, LocalTest, RuntimeEngine/Factory, runtime hooks, Repository, and API/SSE behavior remain unchanged. Add or change no migration, ORM, public HTTP/SSE schema, or frontend. Dynamically verify heads, empty-database upgrade, and migration-directory drift during testing rather than fixing a permanent head constant.
- **Multi-tenancy and identity**: tenant/business/workspace continue to come from trusted scope. Nil never enters selectors, authorization, tenant/credential/Agent queries, DB, logs, metrics, or public data; clients cannot select an Engine or elevate privileges.
- **Reliability**: Preserve leases, Adapter first-terminal-wins, Run-persistence first-commit-wins, late-result protection, and distinct append/finish control flow; deterministic tests cover first-emission gate, ack identity, and cancellation/closure races, leaving no pending owned task.
- **Observability and safety**: Public Result/errors contain only safe enums and static text, and model.completed usage is preserved verbatim. Private history/dropped/Outcome/Context and runtime_emit/worker_emit never enter HTTP/SSE/public engine_metadata; logs and errors leak neither secrets nor raw exceptions.
- **Test evidence**: Real PostgreSQL uses an independent new `pgvector/pgvector:pg17` container with a fresh DB/volume. The connection string exists only in a restricted-permission env file outside the repository, is injected through TEST_DATABASE_URL/AGENT_DATABASE_URL, and is never printed. Local, CI, and human evidence and functional/performance exit criteria remain separate.
