## 1. 验收范围与责任

确认 AC 逐条达成、真实攻击无成功、精确故障点下数据/终态/资源一致，并保留兼容与回退证据。常规验收默认由验收负责人组织并记录结论，执行人准备隔离环境、执行补充检查和整理证据，两者可为同一人；不虚构产品、QA、业务或财务等独立角色。usage 幂等、修正链、聚合重建和零重复计费继续由 A14、C6、C9 及自动对账证据证明，不以财务签字替代技术证据。

**独立审批例外**：是否开放不可信多租户代码执行不属于单人轻量验收范围，必须另附独立安全与 SRE/运维批准，且以真实对抗、故障恢复和回滚证据为依据。没有具备相应职责的人员或证据不足时，`execution_untrusted_tenants_enabled` 必须保持 `false`，不得通过删除流程或签字要求放行。开发者自验不冒称独立安全审计。

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| 类生产强沙箱对抗环境 | 真实不可信任务、网络/文件/资源攻击、Secret canary 和泄露处置。 |
| 多 Worker/Host 故障环境 | SIGKILL、lease/heartbeat、迟到结果、取消/超时/清理和配额恢复。 |
| PG 迁移与事件环境 | 0056/0057 副本升级/回填、Outbox 故障点、usage 台账和审计。 |
| 多 API/SSE 环境 | 多页重放、通知丢失、断线重连、过旧游标和终态追赶。 |
| React/Codex 回归环境 | Phase 0 基线、历史 Run/事件/配置和既有执行路径。 |

**前置条件**：Phase 0~5 已验收；Phase 0 基线已补；`04-test-plan.md` 全部适用用例通过且无 P0/P1；真实沙箱、多 Worker、故障点环境无 pending_env；迁移已在生产数据副本上演练。验收使用可销毁的专用宿主/网络/卷和至少两个专用租户，真实 Secret 禁止入场，仅使用可吊销 canary。

## 3. 功能验收清单（对应 AC-1~AC-16）

| # | 验收步骤 | 通过判据 | 溯源 |
|---|---|---|---|
| A1 | 创建、轮换、吊销凭据；篡改绑定、跨租户读取并移除主密钥。 | 公共视图/存储不明文；版本/吊销生效，全部异常 fail closed 且有审计。 | AC-1；FR-1 |
| A2 | 签发短期 grant，跨 Run、扩大 scope、过期、重放并在 Resume 复用旧 grant。 | 仅原 Run/Engine/scope 可用；其余拒绝，Resume 新签发，审计无 Secret。 | AC-2；FR-2 |
| A3 | 向所有输出面注入 canary，模拟一次真实泄露处置。 | 普通输出脱敏/隔离；凭据吊销、新执行停止、取证无明文，无二次泄露。 | AC-3；FR-3 |
| A4 | 执行逃逸、提权、fork bomb、内存/磁盘耗尽；移除沙箱后启动。 | 攻击被限制/终止，宿主/其他 Execution 无影响；无沙箱拒绝启动。 | AC-4；FR-4 |
| A5 | 执行未授权外联、DNS rebinding、元数据、重定向和代理绕过。 | 实际网络边界全部拒绝，允许清单仅最小生效，无诱饵命中或凭据泄露。 | AC-5；FR-5 |
| A6 | 执行穿越、链接、设备、宿主路径、跨租户与恶意产物攻击。 | 越权全部拒绝，合法文件受控，无可疑产物发布或清理残留。 | AC-6；FR-6 |
| A7 | A 过期、B 接管后，让 A 尝试全部写入和资源释放类型。 | B epoch 更大；A 零有效写/零部分提交，Fencing 审计完整。 | AC-7；FR-7 |
| A8 | 注入 Worker SIGKILL、heartbeat 停顿、lease 过期和旧 Worker 迟到成功。 | 恢复路径明确，唯一终态，旧结果不覆盖，无双 Worker/双终态。 | AC-8；FR-8 |
| A9 | 取消/超时并分别注入退出、hang、清理失败、Worker 丢失，做资源/配额对账。 | 仅确认退出/清理后 cancelled；异常明确告警，无孤儿资源或配额泄漏。 | AC-9；FR-9 |
| A10 | 对启动前失败、模糊超时、外部写入后断连和 Outbox 重试申请执行重试。 | 仅无副作用场景自动重试；模糊/有副作用不盲放，attempt 可追踪且效果不重复。 | AC-10；FR-10 |
| A11 | 混合 v1/新版本事件，注入非法 schema 并并发分配 sequence。 | 历史兼容、版本明确、seq 单调无冲突；非法输入有诊断，历史不重编号。 | AC-11；FR-11 |
| A12 | 重发原生事件，在事务提交和 Outbox 发布前后崩溃。 | 无重复 seq/usage/业务效果；无部分终态，恢复可重扫，event_id 消费幂等。 | AC-12；FR-12 |
| A13 | 制造多页事件、丢通知并断线重连；使用非法/过旧游标追赶终态。 | 保留期无静默缺口，event_id 去重、SSE id 兼容；400/409 正确，最终事件一致。 | AC-13；FR-13 |
| A14 | 重复/重放 usage，提交旧 epoch usage、供应商修正和缺失字段，再重建聚合。 | 同源仅一次，旧 epoch 拒绝，修正可追踪，未知不填零，重建一致。 | AC-14；FR-14 |
| A15 | 注入 malformed/未知/超限/连续错误及 Secret 样本。 | 分类、关联、脱敏、率限和 skip/quarantine/fail 正确，无事件风暴/泄露。 | AC-15；FR-15 |
| A16 | 在数据副本升级规划迁移，灰度/回滚各能力并跑 React/Codex/API/SSE 回归。 | 在线扩展/回填正确，安全不降级、数据不删除，Outbox 无遗漏，Phase 0 diff 为零。 | AC-16；FR-16 |

每个场景记录执行人、日期、环境、版本、攻击/故障点、前置数据、实际结果、判定及日志/DB/Host/网络证据链接。硬门禁环境不可用标 `pending_env`，阶段和不可信开放均不得通过。

**证据复用**：A1～A16 优先直接引用 `06-test-report.md` 中对应的 UT/IT/CM、CI、对抗、故障点、DB、Host、网络与 Outbox/SSE 原始证据，不重复手工执行整套测试。泄露、逃逸、过期写、重复事件/usage/计费和回归 diff 直接按 A/C 判据统计，不另做第二轮业务指标验收；证据复用不减少攻击矩阵、故障点或独立审批例外。

## 4. 少量关键人工检查

仅补自动化证据无法完整覆盖的客户端语义与提示；每项记录执行人、目标 SHA、结果和证据，不另设客户端或业务代表。

| # | 检查 | 通过判据 |
|---|---|---|
| M1 | 在客户端制造断线重连、保留期外重置与瞬时 delta 丢失 | 不重复展示业务事件或静默丢失进展；重置提示明确安全；最终答案与历史事件、现有 Run API 行为一致 |
