# Phase 0 · 基线与盘点 — 业务目标

> 状态：待评审（未开始实施）
> 创建：2026-11-02
> 依据：`docs/architecture/agent-execution-platform-v2.md` 第 15、17 节 Phase 0；后续所有阶段依赖本阶段结论
> 预估工期：~1–1.5 周
> 依赖：目标 `integration` 提交可构建；现有 PostgreSQL 测试环境可用

## 要解决的问题

### 问题 1：重构依据散落在实现中

`core_platform/agent_runtime/worker.py` 直接持有 `runtime`，`applications/platform_runtime/runtime_factory.py` 固定构造 `RuntimeEngine`，而 Run 持久化、租约和事件由 `repository.py` 协作完成。若缺少经目标提交核验的依赖图，拆出 Adapter 与 Orchestrator 时容易漏掉兼容入口、内存注入或测试替身。

### 问题 2：兼容承诺缺少可重复证据

Run 状态、取消竞态、事件语义以及 Agent 草稿/发布快照分布于代码和既有测试中。当前没有面向本次重构的统一基线样本与结果清单，无法证明后续“行为不变”，也无法区分既有缺陷与重构回归。

### 问题 3：扩展决策尚未形成单一基线

Engine/Protocol/Adapter 标识、Run 与 Execution 的首次迁移关系、后续阶段入口条件需要冻结，否则各阶段可能独立发明命名、状态或配置映射。

## 业务目标

| 目标 | 说明 |
|---|---|
| G1：建立可核验现状基线 | 对目标提交形成依赖图、Run 生命周期、事件语义和配置兼容清单，所有结论可定位到代码或测试 |
| G2：建立回归安全网 | 用确定性自动化测试固定现有 ReAct、Worker、仓储、SSE 与配置加载的关键行为 |
| G3：冻结后续设计输入 | 统一标识与阶段入口条件，记录覆盖率、性能和既有缺陷基线，支撑后续排期与验收 |

## 成功指标

| 指标 | 基线（现状） | 目标 |
|---|---|---|
| 核心模块盘点覆盖率 | 未形成统一清单 | Runtime Engine、Worker、Repository、Factory、Composition、Agent Config、扩展契约及 API/SSE 入口 100% 有 owner、调用关系与测试映射 |
| Run 状态与事件语义覆盖率 | 分散在代码和测试中 | 所有代码可达状态转换、取消/超时/失租路径及公开事件类型 100% 登记；未知项必须显式列出 |
| 存量 Agent 配置兼容样本通过率 | 待测量 | 纳入基线的真实脱敏样本与边界样本 100% 可加载；失败样本有既有缺陷记录，不得静默删除 |
| 基线回归结果可复现率 | 待测量 | 同一干净环境连续执行 2 次结果一致；skip/xfail 逐项说明，CI 留存命令与结果链接 |
| 后续阶段未决基线问题 | 未汇总 | P0/P1 阻断问题为 0；其余问题均有 owner、影响阶段和裁定期限 |

## 范围

**包含**：

- 锁定目标提交并盘点执行、配置、事件和组合依赖；
- 记录 Run 生命周期、事件字段、取消/失租/终态语义；
- 建立脱敏配置与已发布快照兼容样本；
- 补充现有行为回归测试并测量覆盖率、耗时和已知 flaky/skip；
- 冻结初始标识、Run=一次 Execution 的迁移约定和重构检查清单。

**不包含**：

- Execution Contract、Registry、Orchestrator 或 React Adapter 实现（Phase 1–2）；
- 多 Engine 配置、Runtime Host、Codex、安全与规模化功能（Phase 3–7）；
- 生产代码重构、历史数据迁移或提升既有功能指标；
- 借基线测试之名重写既有测试来掩盖回归。

## 风险与约束

- **基线过期**：分支继续演进会使结论失效；文档必须记录提交 SHA，后续阶段开工前重核差异。
- **样本不代表生产**：仅使用构造样本会漏掉历史字段组合；需纳入经授权的脱敏快照并记录来源和覆盖边界。
- **既有缺陷阻塞**：基线测试可能暴露问题；先登记并评审，未经裁定不得顺手改变行为。
- **覆盖率误用**：行覆盖率不等于行为兼容；必须同时固定状态、事件、错误与配置语义。
- **兼容性**：本阶段只增加测试和文档；若必须修复既有缺陷，单独提交、单独回滚并更新基线。
