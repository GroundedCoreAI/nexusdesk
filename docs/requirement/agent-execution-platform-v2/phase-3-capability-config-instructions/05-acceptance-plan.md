# Phase 3 · 能力、配置与指令 — 验收方案

> 状态：待实施（本阶段上线前执行；当前无验收结果）
> 创建：2026-11-02
> 依据：`01-business-goals.md`（G1–G4、成功指标）、`02-requirements.md`（AC-1–AC-11）；测试执行依据见 `04-test-plan.md`

## 1. 验收目标与组织

确认本阶段交付物**功能正确**（AC 逐条复现）、**业务有效**（兼容、性能与快照指标达成）、**安全可上线**（客户端不可提权、敏感信息不泄露、开关可回退），并给出签字结论。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 验收主持；配置/预览体验与 P2 遗留处置签字 |
| QA | A1～A11 执行与证据；Phase 0 基线对比、回归和缺陷分级 |
| 研发负责人 | 环境保障；迁移/回滚演练；指标数据与缺陷修复 |
| 安全负责人 | 提权、跨租户、快照敏感信息、策略来源与安全门槛一票否决判定 |
| 运维负责人 | 开关灰度、观测、回退操作与生产适用性确认 |
| 租户管理员代表 | 旧 Agent 无感迁移、新配置和只读 Effective 视图 UAT |

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| 类生产环境（React + 受控模型/工具） | 功能验收、真实配置/性能指标与 Summary/Memory 回归 |
| 专用 PostgreSQL + LocalTestAdapter | 能力分层、启动屏障、失败/取消/超时、跨租户和快照验证 |
| quickstart 双容器（demo 模型） | 默认关闭、旧 React 执行和部署回退承诺验证 |
| disposable 存量库副本 | 在线迁移、并发读写、应用回滚；downgrade 仅在 disposable 库执行 |
| 前端验收构建 | Engine 配置、只读预览、i18n 与错误体验 |

**前置条件**：Phase 0 基线和 Phase 1–2 验收完成；`04-test-plan.md` 全部用例通过且无 P0/P1；实施时已重验迁移 head/down_revision；验收使用至少两个专用 tenant 和独立 scope，不与生产客户数据混用；所有快照与日志证据先经敏感扫描。

## 4. UAT 判定（租户管理员代表）

- 旧 Agent 未出现强制补字段、含义变化或必须重新发布的提示。
- 新 Engine 配置能区分公共字段、React 字段和只读能力；未知/冲突配置的错误可定位且全部使用 i18n。
- 能力预览能解释“不支持”“环境不可用”“策略拒绝”，但不会让管理员误以为声明就是授权。
- 回滚后界面不出现失效的 Phase 3 编辑入口，历史已发布版本和 Run 仍可查看。

| 指标 | 基线 | 目标 | 测量方法 |

| 客户端能力提权成功数 | 待 Phase 0 盘点信任边界 | 0 | A5 原始请求矩阵、审计和安全测试交叉核验 |
| Phase 3 Run 快照完整率 | 待 Phase 0 测量 | 四种终态均 100%，缺失时启动数为 0 | 数据库查询完成/失败/取消/超时样本并核对启动事件时间 |

## 7. 通过标准与签字

- **通过**：A1～A11 全部通过；六项指标达到目标；C1～C10 全过；无 P0/P1 遗留；回滚证据完整。
- **有条件通过**：仅不影响安全、兼容、快照或回滚的 P2/P3 遗留，每条有 owner 与期限；任何一票否决项不适用有条件通过。
- **不通过**：任一 AC、硬指标或否决项失败；Phase 0 基线缺失导致兼容无法判定；出现提权、跨租户、秘密泄露或非 React 静默降级。修复后重验受影响项及完整回归。

输出《Phase 3 验收报告》：AC 执行记录、指标原始数据、合规核对、迁移/回滚证据、遗留清单、结论与签字（产品 / QA / 研发 / 安全 / 运维）。
