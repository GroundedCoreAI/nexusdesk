# Phase 1 · 执行契约与注册中心 — 验收方案

> 状态：待评审 / 待实施
> 创建：2026-11-02
> 依据：`01-business-goals.md`（G1～G4、成功指标）、`02-requirements.md`（AC-1～AC-8）；执行依据见 `04-test-plan.md`

## 1. 验收目标与组织

确认契约与注册中心**可独立扩展、生命周期语义正确、测试确定、现有生产路径零影响**，并由产品、QA、研发和 Adapter 代表签字。本文是验收计划，不表示功能已实现或已通过。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 验收主持；确认范围未蔓延及后续阶段边界；P2 遗留处置签字 |
| QA | 执行 A1～A8、核对测试证据与确定性；回归结论和缺陷分级 |
| 研发负责人 | 提供实现、依赖方向、无迁移/零接线证据；指标测量和缺陷修复 |
| Adapter 开发代表 | 用独立测试 Adapter 做 UAT，确认无需修改公共契约或 Worker |

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| CI / 本地纯 Python 环境 | 契约、注册中心、LocalTestAdapter 全部场景；禁止依赖外部 Engine、凭据和网络 |
| 专用 PostgreSQL 回归环境 | 验证既有 Runtime/API/SSE 未回归及迁移 head 不变 |
| 文档与代码评审环境 | 核对路径、版本、依赖边界、错误脱敏和 Phase 2 非目标 |

**前置条件**：`04-test-plan.md` 全部用例通过，无 P0/P1 未关闭；提供 CI run、测试日志、文件变更清单与 `alembic heads` 证据；验收数据和测试租户专用，不使用真实客户输入或凭据。

## 3. 功能验收清单（对应 AC-1～AC-8）

| # | 验收步骤 | 通过判据 |
|---|---|---|
| A1 | 对应 AC-1：现场运行六类 DTO 正反向参数化用例，并演示修改一个实例的默认集合后读取另一实例 | 所有非法输入被拒绝，版本和 ID 正确；另一实例默认值未变化，证据关联 P1-UT-01～02 |
| A2 | 对应 AC-2：选择成功与流式脚本，按 capabilities→start→stream→collect 顺序执行并核对身份、事件和结果 | 五方法及身份属性符合契约，事件有序，completed 结果与脚本一致，无悬挂任务 |
| A3 | 对应 AC-3：启动长运行场景，连续 cancel 两次，同时释放成功闸门并注入迟到事件 | 两次 cancel 安全；最终仅 cancelled，无成功 output，迟到事件不形成有效新事件或第二终态 |
| A4 | 对应 AC-4：遍历十类错误和能力声明，故意在原始异常/details 放入 `secret-marker` | 分类/code/retryable 符合矩阵；未声明能力为 false；所有面向调用方输出均无敏感标记 |
| A5 | 对应 AC-5：由 Adapter 代表独立添加一个测试 Engine、两个 Protocol 和版本化实现，复用公共套件并两次解析 | 无需改公共契约/Worker；有效组合均通过；两次解析为独立实例且身份匹配 |
| A6 | 对应 AC-6：逐一执行未知 ID、未知版本、未声明组合、禁用、重复冲突和身份不匹配工厂用例 | 全部 fail closed，错误代码稳定，不发生 latest、其他版本或其他 Engine 回退 |
| A7 | 对应 AC-7：运行重复/延迟事件、超时、资源耗尽、模拟进程故障两轮并检查 asyncio 任务 | 语义可重复，异常事件可识别，超时/失败分类正确；无真实外部依赖和 pending task |
| A8 | 对应 AC-8：检查生产 Worker/Factory diff、运行现有 Runtime/API/SSE 回归并查询迁移 head | 新路径未接生产，旧 API/事件/状态无 diff；head 为 `0052`，回归全绿 |

每个场景执行记录必须包含：执行人、日期、环境、前置数据、实际结果、判定、CI/日志链接；失败项不得标为通过或以“仅测试实现”为由豁免。

## 4. UAT 判定（Adapter 开发代表）

- 仅阅读公共契约与注册接口即可完成一个测试 Adapter，不需理解或修改 Worker、Repository、RuntimeFactory。
- 成功、错误和取消场景的诊断足以定位配置/协议问题，但不会暴露原始凭据、config 或客户内容。
- 明确区分 LocalTestAdapter 的模拟进程故障与 Phase 4 的真实进程监管，验收记录不得混称。

## 5. 业务指标验收

| 指标 | 基线 | 目标 | 测量方法 |
|---|---|---|---|
| 契约分支与五方法覆盖率 | 待 Phase 0 盘点 | 定义的契约分支和五方法 100% 有用例且通过 | 导出 P1-UT/IT 溯源矩阵与 CI 结果，逐方法核对，缺失任一项即不达标 |
| 有效/无效组合解析正确率 | 待 Phase 0 盘点 | 固定矩阵有效成功率与无效拒绝率均 100% | 至少覆盖一个 Engine、两个 Protocol、两个版本及全部无效类别，保留每行结果 |
| LocalTestAdapter 场景确定通过率 | 待 Phase 0 盘点 | 规定场景两轮均 100% 通过，无 pending task | 同一环境连续执行两轮，保存独立日志及任务清理断言 |
| 新 Adapter 对公共契约/Worker 修改次数 | 待 Phase 0 测量 | 0 次 | 审查测试专用 Adapter 的变更文件清单与公共套件复用证据 |
| 对现有 Run 延迟与错误率影响 | 待 Phase 0 测量 | 生产行为 diff 为 0，无新增执行开销 | 以零生产接线 diff 和现有回归为验收证据；性能数值不在本阶段虚构，留 Phase 0/2 实测 |

## 6. 合规核对

| # | 核对项 | 判定 |

| C1 | DTO、注册、错误和日志不含明文凭据、连接串、原始堆栈或客户输入 | 一票否决 |
