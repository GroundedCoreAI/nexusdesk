## 1. 验收目标与组织

确认 Stage A 在真实受控 Codex CLI 上稳定后，才验收并解锁 Stage B；确认两种 Protocol 的**功能正确**（AC 逐条复现）、**业务有效**（指标达成）、**安全可上线**（可信租户硬门槛、进程可清理、开关可回退），并给出签字结论。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 验收主持；通用 Run/流式体验判定；P2 遗留处置签字。 |
| QA | AC/A 场景执行与证据；Stage A 门禁与回归结论；缺陷分级。 |
| 研发负责人 | Codex/Host/Session 环境保障；指标数据；缺陷修复与回滚演练。 |
| 安全负责人 | 可信租户、Workspace、凭据与 Secret 对抗验收；不可信租户开放一票否决。 |
| SRE/运维负责人 | 真实进程/连接清理、监控告警、灰度与回退判定。 |
| 可信租户业务代表 | 编码任务 UAT；原生事件与最终结果可用性判定。 |

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| 类生产受控 Codex 环境 | 固定版本真实 CLI/App-Server、低权限专用账号、功能与指标验收。 |
| Phase 4 RuntimeHost/Workspace 环境 | 进程树、挂载、取消/超时/崩溃和清理证据。 |
| PG 迁移与回归环境 | 条件性 Session 迁移、Run/事件持久化、React/SSE 回归。 |
| quickstart（不含真实 Secret） | 默认关闭、部署占位与 React 兼容承诺验证；不冒充真实 Codex 验收。 |

**前置条件**：Phase 0~4 已验收；Phase 0 基线已补；`04-test-plan.md` 全部适用用例通过，无 P0/P1；Stage B 验收另需 P5-IT-18 和连续 3 次预发布回归证据。使用至少两个专用租户和专用 Workspace，不与其他测试数据混用；真实凭据由 Secret 管理并在验收后吊销。

| # | 验收步骤 | 通过判据 | 溯源 |

| A2 | 查询 Engine/Protocol 注册；在无 Stage A 证据和有完整证据时分别尝试开启 App-Server。 | 两者共享 `codex` Engine、Protocol 独立；无证据拒绝，有证据且审批后才解锁。 | AC-2；FR-1 |
| A3 | 分别运行产生消息、命令、文件变更及 usage 的 CLI/App-Server 任务，再运行无 usage 任务。 | 平台与原生事件均保留并关联；usage 准确或显式 unknown，不填零。 | AC-3；FR-4 |
| A4 | 对含子进程的两种执行分别取消、超时，并模拟无法清理。 | 正常情形在宽限期内实际退出并释放资源；异常情形明确失败/告警，无假 cancelled/completed。 | AC-4；FR-3 |

| A7 | 在 Stage B 进行 JSON-RPC 初始化、并发 Turn、断连、未知/迟到响应，检查公共 API。 | ID 关联不串线、异常有终态和诊断、无公共私有协议端点或字段。 | AC-7；FR-7 |
| A8 | 创建 App-Server Session，连续执行多个 Turn/Run，构造过期并重复清理。 | 映射/元数据版本正确，过期后不可 Resume，资源清理幂等，CLI 不受影响。 | AC-8；FR-8 |
| A9 | 在 Effective 允许/拒绝两种策略下请求流式、审批和交互输入，并取消等待。 | 允许路径通用契约可用；拒绝路径无副作用/自动批准；等待有界可取消。 | AC-9；FR-9 |

| A11 | 注入未知版本、坏 CLI 输出、非法 JSON-RPC、缺失 usage，检查错误和遥测。 | 稳定错误/unknown、无原始异常或 Secret；可按 Run/Protocol/版本定位。 | AC-11；FR-11 |
| A12 | 关闭 Codex 全部开关，执行 React、历史配置、Run/API/SSE 回归与回滚。 | Codex 新执行被拒绝；Phase 0 diff 为零；回滚不删表、不改历史 Run。 | AC-12；FR-12 |

每个场景执行记录：执行人、日期、环境、Codex/Adapter 版本、前置数据、实际结果、判定、截图/日志/Host 清理证据链接。真实环境不可用项标 `pending_env` 并指定验收人，不得记为通过。

## 4. UAT 判定（可信租户业务代表）

- 通用 Run 提交、流式进度、审批/输入和最终结果是否符合既有使用习惯，无需理解 Codex 私有协议。
- 原生命令/文件事件是否足以定位任务进展，malformed/失败提示是否可理解且不暴露宿主或 Secret。
- Session Resume 是否保持正确业务上下文；拒绝恢复时是否明确安全，而非静默新建会话冒充恢复成功。
- Stage A 未稳定前产品界面和配置不得向普通用户展示 App-Server 可用。

## 7. 通过标准与签字

- **Stage A 通过/Stage B 解锁**：A1~A6、A11~A12 及 Stage A 对应 C 项全过，P5-IT-18 证据完整，无 P0/P1；Stage B 未解锁不等于本阶段整体通过。
- **通过**：A1~A12 全部通过，硬指标达成，C1~C10 全过，无 P0/P1，真实 Codex 环境无 pending_env。
- **有条件通过**：仅非安全、非 Stage 门禁的 P2/P3 遗留且每条有 owner 与期限，硬指标和全部一票否决项达标。
- **不通过**：任一否决项、Stage 顺序、硬指标或真实环境覆盖未达标；修复后重验受影响项及回归。

输出《Phase 5 验收报告》：Stage A 解锁证据、AC/A 执行记录、指标数据、合规核对、遗留清单、结论与签字（产品 / QA / 研发 / 安全 / SRE）。
