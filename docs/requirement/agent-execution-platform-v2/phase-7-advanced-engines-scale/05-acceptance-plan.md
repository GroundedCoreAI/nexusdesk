## 1. 验收目标与组织

确认每个被评审切片的交付物**功能正确**（适用 AC 逐条复现）、**业务有效**（适用指标达成）、**安全可上线**（重新授权、无副作用重复、开关可回退），并留下可签字的证据。具体上线范围必须逐切片评审；通过某片不代表批准其他片或任何具体厂商 Adapter。

| 角色 | 职责 |
|---|---|
| 产品负责人 | 主持验收；确认切片业务边界与 Effective/等待/降级体验；P2 遗留处置签字 |
| QA | 执行适用 A1~A22、C1~C12 与回归；保存环境、步骤、实际结果和证据；缺陷分级 |

| SRE/Runtime 运维 | 验证多 Worker quota/fairness、Profile 健康/熔断、告警、容量、灰度与回滚演练 |

| 发布负责人 | 确认单片 feature flag、灰度范围、监控、回滚与再启用条件；拒绝 Big Bang 上线 |

## 4. UAT 判定（业务代表）

- 基础能力用户：高级能力缺失时仍能得到明确结果或明确拒绝，不看到无权限/不支持的操作；等待、unknown、熔断文案可理解。
- 会话操作员：Resume 不造成上下文错租或已撤权能力复活；失败原因可操作且不暴露原生 Engine 敏感信息。
- 人工审核员：待办包含足够但最小化的请求上下文、revision/过期状态和决议结果；重复点击不会重复恢复。
- Agent 管理员：动态模型选择理由、版本和旧配置兼容可解释；不能通过界面选择未授权 Profile。
- 财务/运营：报表明确“估算”、覆盖范围、unknown 和币种；不会把 informational 与 additive 相加。
- 运维人员：配额拒绝、熔断打开、半开恢复、回滚和再启用均有可定位事件/告警，不需查看 Secret 或宿主敏感路径。

## 8. 通过标准与签字

- **单片通过**：该片适用 A 场景全部通过；适用硬指标达成；C 项全过；无 P0/P1 遗留；灰度、回滚、监控与证据齐全。
