## 1. 验收范围与责任

确认 AC 逐条达成，清理、隔离、资源与观测判据有证据，不可信执行保持关闭，无越界文件操作、误杀或资源静默忽略，并可排空回滚。默认由验收负责人组织并记录结论，执行人准备隔离环境、执行补充检查和整理证据，两者可为同一人；不虚构产品、QA、业务、安全或运维等独立角色。开发者自验只证明符合本文需求，不冒称真实用户验收或独立安全审计。

## 2. 验收环境与前置条件

| 环境 | 用途 |
|---|---|
| 类生产 Linux + 专用 PostgreSQL | 两 Adapter、真实进程、Run/进程/Workdir 状态、并发与故障验收 |
| Linux cgroup v2 资源专项环境 | CPU/内存/PID/磁盘/时间/输出边界与完整支持矩阵 |
| 隔离文件系统与挂载命名空间 | 穿越、软链/硬链/挂载点、竞态、配额和安全清理；只使用测试哨兵 |
| 可重启 Worker/容器 + 独立执行卷 | 孤儿恢复、PID 复用决策、稳定 host_id、停止排空和回滚 |
| macOS 开发子集/不支持平台对照 | rlimit/监督器近似能力与 required=true 失败关闭，不替代 Linux 完整验收 |
| quickstart 与 production 部署检查环境 | 默认关闭、旧 React、卷归属、停止期限、配置与部署回退 |
| disposable 存量库副本 | 在线迁移、并发读写、应用回滚；downgrade 仅在 disposable 库执行 |

**前置条件**：Phase 0 基线和 Phase 1–3 验收完成；`04-test-plan.md` 全部适用用例通过且无 P0/P1；实施时已重验迁移 head/down_revision；完整验收具备 Linux/cgroup/挂载/容器环境。使用至少两个专用 tenant、独立 scope 与内置可信测试目标，不混用生产客户数据或真实模型密钥。任何环境缺失项标 `pending_env` 并阻断其覆盖的上线承诺，不得跳过或写成通过。
